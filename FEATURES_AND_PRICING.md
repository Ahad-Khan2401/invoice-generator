## 2. Entitlement flow (implemented)

1. User signs in with Google → `/api/auth/google` verifies the token (audience-checked when
   `GOOGLE_CLIENT_ID` is set), hashes the e-mail, syncs subscriptions from the Lemon Squeezy API into
   the `subscriptions` table, and issues an HMAC session token carrying a plan code.
2. Lemon Squeezy webhooks (`/api/webhooks/lemonsqueezy`, HMAC-SHA256 `X-Signature`, idempotent via
   `webhook_events`) keep `subscriptions` current on create/update/cancel/resume/expire/pause/
   payment_failed/payment_success/payment_recovered/order_refunded.
3. Every gated API (`/api/invoices`, `/api/profile`, `/api/clients`, `/api/verify`) calls
   `resolvePlan()` → DB first; the token's plan code is only a UI hint (and the fallback when no DB is
   configured).
4. `/api/verify` (client calls it every 7 days and after checkout) re-issues a token when the plan
   changed, so a cancellation or failed payment is reflected within one verify cycle — or immediately
   on next sign-in.
5. `past_due` keeps access during dunning; `cancelled` keeps access until `ends_at`; `expired`/`unpaid`
   drop to Free. Nothing is deleted on downgrade; the free history limit applies to new saves.

Checkout itself is the hosted Lemon Squeezy overlay (no card data touches our servers); the redirect
to `/?pro=success` only opens the sign-in modal — it never grants Pro by itself.

## 3. Feature inventory

### Implemented in this release
- Four document types (invoice, receipt, quotation, **estimate**) with type-aware labels, numbering
  (`INV-/RCT-/QUO-/EST-`), default notes and statuses.
- Rounding-safe money math (`lib/invoice-math.ts`, unit-tested): half-up 2-dp rounding, totals equal
  the sum of displayed lines, inclusive-tax breakdown shown without changing totals, thousands
  separators, zero-decimal currencies, 18 currencies.
- PDF engine: JPEG compression, A4 / US Letter, fixed 96-dpi page width (identical output on phone and
  desktop), page breaks only at row/block boundaries, "Page x of y" footer, PDF metadata.
- Generator UX: responsive two-row item grid on phones, labelled inputs, fractional quantities, Enter to
  add row, non-blocking validation panel, auto-increment numbering, New / Duplicate / Save draft /
  Export JSON / Restore JSON, convert quotation→invoice, receipt from paid invoice, PO number, tax label
  (VAT/GST/HST/…), paper size toggle, page-count badge.
- Business profile: remembered on device (guest) and synced to the account (`/api/profile`).
- Client directory (`/api/clients`) with picker and one-click save; limits per plan.
- Dashboard: outstanding/overdue/paid summary, search, filters, mark paid/unpaid, delete, duplicate
  (`/?dup=`), re-edit (`/?load=`), copy payment-reminder e-mail, CSV export (Pro).
- Shared auth context: sign-in works from every page; Pro users see no ads.
- Analytics events (no PII): generator_started, document_type_selected, template_selected,
  pdf_generated, pdf_downloaded, print_started, draft_saved, document_exported/imported,
  signup_started/completed, signin_completed, pricing_viewed, checkout_started (+ GA4
  `begin_checkout`), subscription_activated, premium_feature_clicked, reminder_copied, csv_exported.

### Not implemented (and why)
| Feature | Blocker / decision |
|---|---|
| Recurring invoice scheduling, e-mailed reminders | Needs an e-mail provider (Resend/Postmark) and a scheduler (Vercel Cron). Reminder *drafts* are implemented instead. |
| AI-assisted invoice drafting | Needs an API key and a cost ceiling. Design: `POST /api/ai/draft` → Claude with a strict JSON schema (items, qty, rate, notes only; never tax rates, status, client data) → user reviews in the form before download; rate-limited per IP, 10/day free, 100/day Pro; disclosed in the UI and privacy policy. |
| Bulk generation, team seats, multiple profiles UI | Business plan is config-scaffolded; build the UI once a Business product exists in Lemon Squeezy. |
| Online payment links on invoices | Would require Stripe/PayPal integration and regional checks; out of scope. |
| Shareable online invoice links | Requires public read endpoints and expiry handling; defer until demand is seen. |

## 4. AdSense posture (reviewed)
- Ads only between content blocks (`AdSlot`), labelled "Advertisement", 100 px reserved (CLS), never
  inside the generator, never near Download/Print, never in modals. Script loads `lazyOnload`.
- Paid plans see no ads (previously advertised but not implemented — fixed).
- Consent Mode v2 default-denied in EEA/UK/CH; AdSense CMP handles the message.
- Planning formula from the brief: revenue = pageviews × RPM / 1000. At an assumed $3–5 RPM, $300/month
  needs 60k–100k monthly pageviews; current traffic is unknown without GA access. Track RPM in
  AdSense → Reports and pageviews in GA4; do not add ad density until RPM data exists.
